# 小和的奇妙数学之旅 —— v2 架构说明

这是按照咱们定的设计规范（导/解/史/练 四按钮、三态图标、进度记忆、目录页）重新搭的一版，
和你之前 GitHub 上那个最初的 demo 相比，**几乎每个文件都变了**，属于整体升级，不是小修小补。

## 这一版实现了什么

- ✅ 封面 → 点"开始阅读"进入漫画
- ✅ 左右滑动翻页（10页，第1页是"清晨阳光洒满草坡"，第10页是"得想个办法"结尾）
- ✅ 每页底部四个按钮：导 / 解 / 史 / 练，只有这一页真的有内容时才会亮起来，
  没有内容的按钮是灰色虚线"幽灵"样式（现在只有第1页的"导"和第5页的"史"是亮的，其余8页四个都是灰的——这是符合你的要求的正确状态，不是 bug）
- ✅ 三种视觉状态：灰色虚线幽灵（无内容）／彩色实心（待完成）／浅蓝打勾（已完成）
- ✅ 点开"史"卡片有 🔊 朗读按钮，用手机系统自带的语音朗读文字内容
- ✅ 点开"解"或"练"会响一下庆祝音效（当前10页里这两个按钮还没有内容，所以暂时用不上，但功能已经做好了，以后写到有例题的页面直接用）
- ✅ 顶部"☰"目录按钮，点开可以看到全部10页的完成状态，点任意一页可以直接跳转
- ✅ 阅读进度自动保存在手机本地——关掉 App 下次打开会自动回到上次读到的那一页

## 以后怎么给某一页加内容

打开对应的 `content/PXX.js` 文件，把 `null` 换成一个内容对象。四种类型的格式分别是：

**导 / 史**（纯文字讲解，格式相同）：
```js
guide: {
  id: 'guide_某个独一无二的英文标识',   // 完成状态靠这个 id 记录，不要和别的重复
  title: '这张卡片的标题',
  body: '正文内容，如果想分段，用两个换行符隔开就行，像这样\n\n这是第二段'
},
```

**解**（如果是竖式加减法演示，可以直接用现成的通用组件，不用整段重写）：
```js
explain: {
  id: 'explain_某个独一无二的英文标识',
  title: '进位加法：36 + 47',
  tag: '知识讲解 · 加法竖式',
  calc: { op: 'add', a: 36, b: 47 }   // op 填 'add' 或 'sub'，会自动生成"下一步"演示
},
```

**练**：
```js
practice: {
  id: 'practice_某个独一无二的英文标识',
  title: '延伸练习',
  question: '小和有15只羊，又买了8只，一共几只？请列出算式并计算。',
  answer: '15 + 8 = 23（只）'   // 选填，不写这个字段就不会出现"看看答案对不对"按钮
},
```

**记住**：每个内容对象里的 `id` 字段一定要保证全书唯一，不要两页复制粘贴内容后忘记改 `id`，
否则两页会被系统认成"同一个内容"，共享同一个完成状态。

## 怎么在本地测试

和之前一样，双击 `index.html` 就能直接看效果——**这次特意设计成不依赖网络请求读取内容**，
所以双击打开完全能用，不需要像"添加到主屏幕"那样必须开本地服务器。

如果想测试完整 PWA 效果（添加到主屏幕、离线缓存），还是老办法：
```bash
python3 -m http.server 8080
```
然后手机同一 WiFi 下访问 `http://电脑IP:8080`。

## 上传到 GitHub 需要注意的地方

因为几乎所有文件都变了，这次上传建议：

1. `index.html`、`manifest.json`、`sw.js` —— 直接上传覆盖旧的同名文件
2. `icons/` 文件夹里的两个图标 —— 内容没变，可以不用重新传
3. `images/` 文件夹 —— 这次是从你新发的 PDF 提取的11张图（cover + P01~P10）。
   如果你本地已经有单独存好的、质量更好的同名 PNG，建议用你自己的文件上传覆盖，效果会更好
4. `content/` 和 `audio/` —— 这是全新的文件夹，之前仓库里没有，这次是新增上传，不是覆盖

上传方式还是老办法：进入对应文件夹（或仓库根目录）→ Add file → Upload files → 拖进去 → Commit changes。
`content/` 和 `audio/` 这两个文件夹在 GitHub 网页端可以直接把整个文件夹拖进上传区域，
GitHub 会自动帮你建好文件夹结构。
